How this POC actually fits together

blue — a decision OPA actually makes · amber — MinIO's own IAM, no OPA involved · gray — plain plumbing (HTTP, SQL). Notice the backend never talks to Airflow at all — Airflow's own opa_auth_manager asks OPA natively, independent of everything this UI does.

One Postgres instance, three separate databases (demo, authz, airflow) — never one database serving double duty. Trino and Airflow each hold their own native connection to OPA; the backend's connection to OPA is a third, independent one, used only to preview decisions for this UI and to push policy_data after every grant/revoke.

Where everything is reachable

Computed from this page's own hostname, not a hardcoded IP — works whether this is docker-compose (localhost) or a NodePort in Kubernetes (whatever node address you used to reach this UI). OPA and Postgres are internal-only on the Kubernetes deployment — nothing in the browser talks to them directly, so they're listed without a link there.

Demo credentials

Lab-only values, same across docker-compose and Kubernetes unless noted — never do this for a real deployment. Airflow's passwords are the one exception: SimpleAuthManager generates a fresh random password for each user every time the apiserver process starts, printed once to that pod's own logs — there's no fixed value to show here.
